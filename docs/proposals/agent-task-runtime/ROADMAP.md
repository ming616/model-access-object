# 建设路线

## 当前：项目定位与接口草案

- 明确任务上下文和记忆的持久化归属。
- 明确 Team、运行时容器、MAO、MSCP 和 TaskStore 的职责。
- 准备 API 草案、检查点样例及使用说明。
- 筹备独立仓库 `agent-task-runtime`。

当前阶段尚无 ATR 运行时实现及安装包。

## 首轮：可恢复的最小任务运行时

- TaskRecord 和 TaskContext 数据结构。
- 可替换的 TaskStore 接口及 SQLite 实现。
- 角色工厂登记、任务运行作用域及依赖注入。
- Team 提供初始工作和后续动作的接口。
- 单进程、单事件循环中的逐步执行与步骤边界检查点。
- 暂停、恢复和取消的资源清理。
- 对在途未确认工作及定义版本不匹配的显式处理。
- 申报书初稿、审阅、修改的任务恢复示例。

验证重点：新进程恢复、任务间隔离、反馈终止、版本冲突、取消清理以及未确认工作处理。

## 后续：协作执行能力

根据实际 Team 案例增加并行分支、结果汇合及上下文更新的冲突处理。业务协作规则继续由 Team 定义。

## 后续：跨任务与部署扩展

接入用户或项目的长期记忆；增加任务定义及记录的版本迁移。集中式任务调度、多进程执行所有权、跨机器恢复根据部署需求逐步建设。

## 发布安排

先完善项目源代码、文档和验证案例。打包与版本发布另行规划。
