# 架构与项目边界

## 持久化中心

以任务为持久化中心，用稳定的 `task_id` 关联输入、执行状态、上下文、记忆和成果。角色类及工厂通过 Team 定义登记；执行时创建对象并注入依赖。

任务恢复时读取 Team 定义标识及版本，验证本地具有对应定义，重新创建 Agent，再加载相应上下文。Agent、MAO、MSCP 及其 HTTP 客户端、锁、租约等运行对象由运行环境重新装配。

任务上下文中可记录模型调用的可审计元数据和已产生的结果。模型服务会话、模型资源租约与业务任务具有各自的生命周期。

## 核心组件

| 组件 | 主要职责 |
| --- | --- |
| TeamDefinition | 登记角色工厂，提供初始工作项、后续工作和完成条件 |
| AgentContainer | 在一次任务运行作用域内创建和复用角色实例，注入依赖并完成清理 |
| TaskContext | 承载任务共享数据、角色参与位置的私有上下文及任务记忆 |
| TaskStore | 事务性保存和读取任务记录，检查记录版本 |
| TaskRuntime | 按 Team 提供的动作推进任务，提交检查点，协调暂停与恢复 |

以上首先作为同一项目中的模块建设。首轮验证采用单进程、单个异步事件循环和 SQLite 存储。

## 任务上下文的归属

共享上下文保存目标、资料、成果版本和协作进度。私有上下文按任务内的参与位置隔离，例如 `writer-main`、`reviewer-main`；同一角色参与多个子任务时可使用不同位置标识。

参与位置标识是任务中的上下文键，可由新的运行对象再次使用。上下文和记忆都归属于任务。跨任务的用户偏好、项目知识和长期经验，后续通过独立的记忆服务接口组合。

保存的历史信息与本次发送给模型的消息具有不同范围。角色 Agent 按业务需要选取资料，MAO 完成访问请求的整理。历史可以保留完整记录，并向模型提供相关片段或摘要。

## 生命周期与资源所有权

应用启动时组装 MSCP、MAO、工具及 TaskStore，登记 Team 定义。

一次任务运行中，容器按角色和参与位置创建 Agent；同一作用域中的对象可以复用。任务暂停、结束或运行环境退出时，容器清理自己创建的实例及临时资源。

应用共享的 MAO、MSCP 和存储客户端由应用生命周期管理。结束一个任务作用域时，应用共享组件继续服务其他任务。

## 协作机制

Team 负责确定工作项的角色、输入、成果要求、下一步动作和业务终止条件。ATR 提供统一的执行与保存机制。

依赖装配关系描述角色所需组件；业务协作图描述工作项之间的交接、分支和反馈。协作图可以包含循环，具体循环次数及完成标准由 Team 定义。

首轮执行器逐项推进工作。接口保留多个待执行工作项，并使用唯一 `work_id` 区分反馈轮次和同角色的不同任务。并行执行及多实例共享状态合并在后续验证。

## 检查点的一致性与恢复

任务检查点同时保存成果、上下文更新、已完成工作以及下一批待执行工作。TaskStore 在一个事务中提交这些数据，并通过 `revision` 防止旧记录覆盖新记录。

执行外部调用前登记当前在途工作，完成后提交结果及后续动作。正常暂停在步骤边界生效。恢复时检查最后的在途记录：已经确认完成的工作从下一步继续；未确认的工作交由 Team 的恢复策略处理。

外部系统操作与任务存储之间可能存在未确认的执行区间。涉及提交、发送等副作用的工作应带稳定操作标识，并由业务适配器核对结果或执行幂等处理。首轮项目不承诺任意外部调用的恰好一次执行。

## 首轮验收

- 两个任务的上下文和私有历史彼此隔离。
- 保存任务后，新的进程可读取同一任务并从待执行工作继续。
- 完成初稿的任务恢复后直接进入审阅；已保存成果保留。
- 反馈修改产生新的工作标识，并受 Team 的终止条件约束。
- 任务作用域关闭后，已借用的模型资源及时归还。
- 旧版本写入被拒绝；在途工作和定义版本不匹配产生明确的恢复提示。
